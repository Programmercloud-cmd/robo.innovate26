# External fixed-layout camera feed

Normal operation uses the existing combined supervisor (do not start a second instance):

```bash
/usr/bin/python3 -s digital_twin/perception/launch.py
/usr/bin/python3 -s -m unittest discover -s teaching/external_layout -p 'test_*.py' -v
```

The supervisor owns one external C920 serial `03FB123F`, device reconnection, the display forwarder, robot-image guard and source exclusions. Inspect shared `output/raw.jpg`; never open another camera reader. Standalone `run.py` publishes uncertain observations until the first valid `output/source_exclusions.json` snapshot arrives from the forwarder. No component here connects to the robot or changes inventory, taught poses or world calibration.

`config.json` contains twelve known4×3 footprints. IDs are `external_rR_cBANK_mM_nN`: rows0–5 top-to-bottom, banks0–1 left-to-right, columns m0–2 left-to-right and bricks n0–3 top-to-bottom. Bank0 maps to four-brick pick `R_M`; bank1 is display-only. Metric schematic/tape dimensions are provenance, not image-pixel calibration or execution coordinates.

`registration.py` segments complete warm-pigment bodies within the known-layout neighborhood. Unique size/position assignments, robust common image fit, full-shape residuals and support spanning at least3rows/both banks are required. The normal displacement limit is24px. A shift up to36px additionally requires independent fixed right tape/cross-corner agreement (normalized match≥.90, fitted-vs-observed residual≤3px) and displacement along the row axis below45%of the minimum reference row pitch. Rotation2°, scale change3.5%, fit residual2.5px and full-shape residual6px limits are unchanged. Large/ambiguous changes, inadequate support and occlusion remain uncertain. A footprint with any departed column cannot anchor registration; its remaining columns may still be observed independently after other stacks establish the fit.

The current frame is warped into reference-image coordinates, keeping color sampling, white-gap checks, lamp/cable masks and temporal checks consistent. Debug overlays show the transformed individual samples plus full segmented body boundaries on the original current image. This is bounded image registration; no robot/world reconstruction or live grasp planning occurs.

Fresh measured robot motion vetoes observations. During telemetry outages, the explicit `unknown_camera_evidence_only` mode permits occupied observations only with fresh registered image/pigment evidence and local motion/foreground checks. The user-authorized display-only manual-exchange mode also permits EMPTY with unknown telemetry, but only from independently captured white floor/material evidence, at least98%matching white pixels, stricter brightness/reference difference and confidence≥.8, plus local motion/foreground and temporal confirmation. Fresh measured robot motion remains a veto. Color absence, shadow and occlusion never imply empty. Physical source-removal/parallax validation remains pending.

Source exclusions are read-only snapshots from the root display/controller adapter. Fresh valid snapshots replace the set (the upstream publisher handles explicit controller resets); stale/malformed snapshots retain the previous set. No prior valid snapshot means all observations are uncertain. Excluded slots publish `transferred_source`, never a freshly inferred occupied/empty state. Persistent display memory and transferred-column ownership belong to the separate twin fuser.

Per-frame color confidence remains heuristic. Existing coverage, separation and confidence thresholds are unchanged;3of5 current matching observations confirm occupied colors. A currently uncertain frame always remains uncertain. The operator-confirmed reflected-light prototype applies only to `r0c1m2n1`; it does not copy its neighbor's color or alter other slot palettes.

`latest.json`, `raw.jpg` and `overlay.jpg` are coherent under `output/publish.lock`; readers take a shared lock and expire original camera timestamps.
